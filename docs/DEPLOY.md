# Постоянная работа

Сервис API принимает команды из чата. Отдельный worker проверяет очередь раз в минуту, готовит тексты за час до слота и отправляет их в согласованное время. Данные находятся в SQLite на постоянном диске.

## Docker Compose

После `uv run threads-factory init`:

```bash
docker compose up -d --build
docker compose logs --tail=50 api worker
```

API слушает `127.0.0.1:8000`; база находится в named volume `factory-data`. Не удаляй этот volume, если нужна история. И API, и worker используют один и тот же экземпляр данных. Внутри volume один worker удерживает файловую блокировку.

Для ChatGPT Actions поставь HTTPS reverse proxy перед API. Например, отдельный Caddy на том же сервере:

```caddy
threads.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

Укажи свой настоящий домен в DNS и `PUBLIC_BASE_URL`, затем пересоздай контейнеры. Не публикуй порт SQLite и не делай `.env` доступным через веб-сервер. API имеет Bearer-аутентификацию; `/health` возвращает только `ok`.

## Без Docker

Запусти два постоянных процесса в папке репозитория:

```bash
uv run threads-factory serve
uv run threads-factory worker
```

Для работы после закрытия терминала используй системный менеджер процессов с рабочей папкой этого репозитория и автоматическим перезапуском. Компьютер/сервер должен оставаться включённым. Открытая вкладка ChatGPT или Claude для отправки уже настроенных публикаций не нужна.

## Обновления и сбои

- Сделай резервную копию named volume или `var/`, обнови код и перезапусти процессы. `.env` и база в Git не хранятся.
- `generation_failed`: проверь ключ, модель, формат ответа или отклонённый текст. Автоматического повторного платного запроса для этого слота нет.
- `generation_unknown`: запрос генерации мог быть выполнен; второй запрос не отправляется автоматически.
- `blocked`: аккаунт изменился или провайдер явно отклонил отправку. Подключи и подтверди нужный аккаунт, затем согласуй новый план.
- `unknown`: отправка могла состояться. Worker делает только GET-проверки по сохранённому request_id; новый POST не отправляется. При долгом отсутствии результата проверь профиль и историю Upload-Post вручную.
- `expired`: окно опоздания 30 минут прошло. Исторические слоты массово не воспроизводятся после запуска сервера.
- `cancelled`: профиль/расписание изменено или включена пауза. Текст остаётся в истории и может быть заново согласован.

У API и модели могут быть тарифные ограничения. Пополнение баланса поставщика и изменение тарифа не выполняются автоматически.
