# Подключить управление из чата

Каждый пользователь запускает свой экземпляр и использует свои аккаунт и ключи. Один экземпляр обслуживает одного владельца. Ключи создателя репозитория в комплект не входят.

## ChatGPT: личный GPT с Actions

1. Запусти API и worker по README. Для доступа из ChatGPT сервису нужен доступный снаружи HTTPS-адрес. Локальный `127.0.0.1` виден только твоему компьютеру.
2. В `.env` задай `PUBLIC_BASE_URL=https://твой-домен`, перезапусти API и экспортируй схему:
   ```bash
   uv run threads-factory schema --url https://твой-домен > openapi.json
   ```
3. Создай **личный** GPT. В его Instructions скопируй `AGENT.md`, в Knowledge добавь `reference/БАЗА_ДЛЯ_AI.md`. Это рабочая база контекста, а не обещание дообучения модели.
4. Добавь Action и импортируй `openapi.json`. Authentication → **API Key → Bearer**. В защищённое поле вставь `FACTORY_API_KEY` из своего `.env`. Не отправляй этот ключ сообщением чата и не выкладывай его на GitHub.
5. Протестируй `getFactoryStatus`. Должно вернуться твоё состояние с выключенным расписанием. Начни интервью.

Не публикуй GPT с общим ключом своего экземпляра для посторонних: у него доступ к твоему профилю и очереди. Этот вариант предназначен для личного использования. Для общего многопользовательского сервиса нужна отдельная система пользователей и OAuth, которой в этом небольшом self-hosted инструменте нет.

Официальная документация: [GPT Actions](https://developers.openai.com/api/docs/actions/getting-started), [аутентификация Actions](https://developers.openai.com/api/docs/actions/authentication). Доступность редактора GPT и Actions зависит от интерфейса и разрешений аккаунта. Если инструментов в твоём клиенте нет, остаётся режим подготовки текстов с ручной постановкой в очередь.

## Claude Desktop / Codex: MCP через stdio

API и worker должны работать отдельно. Установи зависимости `uv sync --extra mcp` и добавь сервер в конфигурацию MCP своего клиента:

```json
{
  "mcpServers": {
    "threads-content-factory": {
      "command": "uv",
      "args": ["--directory", "/АБСОЛЮТНЫЙ/ПУТЬ/threads-content-factory", "run", "threads-factory", "mcp"]
    }
  }
}
```

Процесс прочитает `.env` в папке репозитория. Если API находится на другом сервере, добавь в конфигурацию этого MCP-сервера `env` с `FACTORY_BASE_URL=https://твой-домен` и `FACTORY_API_KEY` своего экземпляра. Это настройка клиента, не сообщение ассистенту.

Перезапусти MCP-клиент, убедись, что доступен `get_factory_status`, и отправь стартовый запрос из START.md. MCP предоставляет девять инструментов и ресурс `factory://instructions`.

Эта конфигурация — локальный stdio-сервер. Для Claude в браузере нельзя просто вставить локальный путь как URL удалённого MCP: используй поддерживаемый локальный MCP-клиент либо отдельное развёртывание удалённого MCP с корректной авторизацией.

SDK: [официальный Python MCP SDK, совместимая линия v1](https://py.sdk.modelcontextprotocol.io/v1/).

## Подключить Threads

Один раз создай аккаунт [Upload-Post](https://www.upload-post.com/) и получи свой API key. Введи его через `threads-factory init`. Ассистент создаст/найдёт профиль и выдаст одноразовую ссылку подключения. Ты войдёшь в Threads на стороне провайдера; пароль инструменту не передаётся. После подключения ассистент покажет фактический handle и попросит подтвердить аккаунт.

Свои Meta App ID и Secret для этого пути не требуются: OAuth обслуживает Upload-Post. Его тариф, квота и правила платформы действуют отдельно. Инструмент не обещает бесплатный или безлимитный доступ к API.

Первую публикацию проверь вручную в нужном аккаунте. Локальные тесты проверяют контракт API и поведение очереди; они не заменяют твоё OAuth-подключение и живую публикацию.
